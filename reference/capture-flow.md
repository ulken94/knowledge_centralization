# 커밋 트리거 캡처 절차

commit-capture 훅이 "[kc] git commit 감지" 신호를 줬을 때 따르는 절차.
`$VAULT_PATH`, 작성자 이름은 `~/.claude/kc/config`에서 읽는다.
환경변수 `KC_DIR`가 설정돼 있으면 이 문서의 `~/.claude/kc`를 그 경로로 대체한다 (훅과 동일 규칙).
승인·선택을 물을 때는 이 플러그인의 `reference/asking.md`를 따른다 — 평문으로 묻지 말고 선택지로 고르게 한다.

## 0. 기록 가치 판단

방금 커밋의 내용과 이 세션의 작업 과정을 돌아본다:
- 사소한 커밋(오타·포맷·단순 버전업·기계적 리네임) → **아무것도 하지 않는다. 사용자에게 언급도 하지 않는다**
- 의미 있는 일단락(결정, 시도와 폐기, 설계 변경, 조사 결과) → 1로 진행

## 1. 프로젝트 등록 (미등록 repo인 경우만)

등록이 정하는 것은 **"이 repo에서 나오는 작업은 기록할 가치가 있다"**와 **기본 프로젝트**까지다.
개별 노트가 어느 프로젝트로 갈지는 등록이 아니라 2절에서 내용을 보고 정한다 —
한 repo의 작업이 늘 한 프로젝트에만 속하지는 않는다.

- **슬러그를 짓기 전에 vault에 대응하는 프로젝트가 이미 있는지 먼저 찾는다**:
  `grep -rl '^type: project-index' "$VAULT_PATH/projects"`
  - 같은 작업을 가리키는 프로젝트가 이미 있으면 **그 슬러그를 그대로 쓴다** — 로컬 매핑만 빠진 상태다.
    슬러그는 repo 디렉토리명과 다를 수 있다(예: repo `knowledge_centralization` ↔ 프로젝트 `kc-plugin`).
    디렉토리명으로만 지으면 이미 있는 프로젝트 옆에 중복 프로젝트가 생긴다
  - 없을 때만 repo 디렉토리명 기반 kebab-case 슬러그를 새로 제안한다
- 어느 쪽이든 "이 repo를 vault 프로젝트로 등록할까요?"로 확인받는다
- vault에 같은 시스템·고객의 프로젝트가 이미 있으면 **그룹으로 묶는 안을 함께 제안**한다
  (`projects/<그룹>/<슬러그>/`, `system:` 키 동일값, 그룹 노트 `<그룹>.md` 생성·갱신). 기존 프로젝트도 그 그룹으로 옮겨야
  하면 그 이동까지 한 제안으로 묶는다 — conventions.md "프로젝트 식별과 그룹" 참조
- 승인 시:
  - 등록 경로는 **주 워크트리 루트**의 정규 경로를 쓴다. `git worktree`로 판 디렉토리에서
    등록하면 워크트리를 지운 뒤 죽은 매핑이 남고, 워크트리마다 중복 등록된다:
    `cd "$(git rev-parse --path-format=absolute --git-common-dir)/.." && pwd -P`
    (훅도 같은 규칙으로 환산해 대조하므로 형태가 같아야 매칭된다)
    `printf '%s\t%s\n' "<주 워크트리 정규 절대경로>" "<슬러그>" >> ~/.claude/kc/projects.tsv`
  - **이미 있는 프로젝트에 연결한 경우 vault는 건드리지 않는다** — 매핑 한 줄만 추가하고 끝낸다
  - vault에 프로젝트가 아직 없을 때만 `$VAULT_PATH/_meta/templates/project-index.md`를 기반으로
    `projects/<슬러그>/<슬러그 마지막 구성요소>.md` 생성
    (인덱스 파일명은 repo 디렉토리명이 아니라 **자신이 든 vault 디렉토리명**과 같게)
    (목적·현재 상태는 사용자에게 한두 문장 묻거나 이 세션의 맥락으로 채운다),
    `projects/<슬러그>/context/` 디렉토리 생성, vault-git-flow.md 절차로 커밋·push
- 거절 시 종료. 이 세션에서 다시 제안하지 않는다

## 2. 초안 제안

- `$VAULT_PATH/_meta/conventions.md`를 읽고 스키마·배치 기준·링크 규칙을 따른다
- **초안보다 먼저 기존 노트를 찾는다** (conventions.md "중복 처리"). 찾는 범위는
  매핑된 프로젝트가 아니라 **vault 전체**다 — `projects/` 전체의 `context/` 목록,
  `topics/`, frontmatter `topics:`, 제목·본문 키워드로 검색한다. 겹치는 노트가 있으면
  그 경로를 보여주고 **기존 노트 보완 / 새 노트 / 기록 안 함** 중에서 고르게 한다
- 이 세션의 작업 과정에서 **사고의 흐름**을 요약한 초안을 만든다:
  배경 / 사고의 흐름(무엇을 시도 → 왜 폐기 → 왜 이 선택) / 결론 / 다음 단계·미해결 / 연관
- conventions.md "노트 분할 기준"을 따른다 — 성격이 다른 항목이 여러 건이면
  항목별로 노트를 나누고 서로 링크한다
- **배치는 내용이 정한다. 훅이 알려준 슬러그는 기본값일 뿐이다** (conventions.md "배치 기준").
  vault의 프로젝트 목록을 실제로 훑고(`grep -rl '^type: project-index' "$VAULT_PATH/projects"`)
  이 작업의 내용이 어디에 속하는지 판단한다:
  - 기본값과 다른 프로젝트가 맞으면 **그쪽을 제안한다**. 왜 그렇게 봤는지 한 줄로 밝힌다
  - 여러 프로젝트에 걸치면 **노트를 쪼개** 각각 제 프로젝트에 두고 `## 연관`으로 잇는다
  - 판단이 갈리면 프로젝트 목록을 보여주고 고르게 한다.
    어느 곳에도 안 맞으면 새 프로젝트를 만들지 물어본다 — 임의로 만들지 않는다
- 프로젝트 종속 → `projects/<슬러그>/context/<주제>.md`,
  범용 지식 → `topics/<주제>.md` (출처 프로젝트 링크는 반드시 남김)
- frontmatter `topics:`와 `## 연관` 위키링크는 쌍으로 생성
- **비밀정보(자격증명·비밀키·내부 전용 URL)는 절대 포함하지 않는다**
- 초안 전문을 사용자에게 보여주고 확인받는다

## 3. 사용자 선택

- **승인**(수정 요청 반영 포함) → `status: approved`로 vault-git-flow.md 절차대로 반영
- **"나중에"** → 대기열 등록만 하고 종료:
  `printf '%s\t%s\t%s\t%s\t%s\n' "$(date +%s)" "manual-$(date +%Y%m%d%H%M%S)" "<cwd절대경로>" "<슬러그>" "-" >> ~/.claude/kc/queue.tsv`
- **거절** → 아무것도 하지 않는다. 강제하지 않는다
