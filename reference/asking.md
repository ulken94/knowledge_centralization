# 사용자에게 승인·선택을 물을 때

kc가 승인이나 선택을 물을 때는 **평문으로 묻고 타이핑하게 두지 않는다.**
선택지를 제시하는 질문 도구(`AskUserQuestion`)로 고르게 한다.
답이 예/아니오뿐이어도 마찬가지다 — "진행할까요?"를 문장으로만 던지지 않는다.

## 규칙

- **선택지는 다음 동작이 드러나게 쓴다.** "예 / 아니오"보다
  "이대로 반영 / 고쳐서 반영 / 기록 안 함"처럼 고르면 무슨 일이 일어나는지 보이게 한다
- **권장안이 있으면 맨 앞에 두고 라벨 끝에 `(권장)`을 붙인다.** 왜 권장인지는 설명에 한 줄
- **거절 선택지를 반드시 넣는다.** 기록을 강제하지 않는다는 원칙이 선택지에도 보여야 한다
- 여러 건을 한꺼번에 승인받을 때(큐레이션 제안 목록, conventions 갱신 항목)는
  **다중 선택으로 항목별로** 고르게 한다. 묶어서 전부 아니면 전무로 만들지 않는다
- **초안·차이(diff) 전문은 질문 전에 본문으로 먼저 보여준다.** 선택지 라벨에 요약만 넣고
  정작 반영될 내용을 감추지 않는다

## 예외

값을 받는 경우(vault git URL, 작성자 이름 등 자유 입력)는 그대로 묻는다.
단 제안할 기본값이 있으면 그 기본값을 선택지로 함께 제시한다 —
`git config user.name` 값이나 유도한 clone 경로처럼.
