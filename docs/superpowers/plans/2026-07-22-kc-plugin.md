# kc-plugin (팀 지식 중앙화 플러그인) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 팀 작업(코드·PPT·문서)의 사고의 흐름을 git 기반 Obsidian vault에 캡처·관리·제공하는 Claude Code 플러그인 `kc`를 만든다.

**Architecture:** 플러그인은 8개의 슬래시 명령(`commands/*.md`), 2개의 훅 셸 스크립트(커밋 감지·세션 종료 대기열), 공유 절차 문서(`reference/`), vault 템플릿(`templates/`)으로 구성된다. 상태는 vault(git repo)와 `~/.claude/kc/`의 로컬 설정 파일 3개(config, projects.tsv, queue.tsv)에만 존재한다. 훅은 신호·대기열 등록만 하고(API 호출·vault 쓰기 금지), 지능이 필요한 일은 전부 세션 내 Claude가 명령·reference 문서의 지시대로 수행한다.

**Tech Stack:** Claude Code plugin (markdown commands + hooks), bash, git(순수 명령만), python3(훅의 JSON 파싱 전용)

**Spec:** `docs/superpowers/specs/2026-07-22-team-knowledge-plugin-design.md`

## Global Constraints

- 플러그인 이름은 **`kc`** — 명령이 `/kc:init` 형태가 되기 위한 조건. 명령 이름은 스펙의 명명 원칙(§3)을 따른다: `init`, `commit`, `status`, `review`, `pull`, `curate`, `onboard`, `ask`
- vault 조작은 **순수 git 명령만** 사용 — `gh` CLI·GitHub API 절대 금지 (self-hosted git 전제)
- 노트·사용자 대면 텍스트·커밋 메시지는 **한국어**
- **vault에 쓰기 전 반드시 사람 검토** — 어떤 명령·훅도 검토 없이 vault를 수정하지 않는다
- 훅 스크립트는 **대기열 등록/신호만** 한다 — 훅에서 API 호출·vault 쓰기 금지, 항상 exit 0 (세션을 절대 방해하지 않는다)
- 외부 의존성은 bash + git + python3만. **jq 등 추가 설치가 필요한 도구 금지**
- 로컬 상태 파일: `~/.claude/kc/config`(KEY=VALUE), `~/.claude/kc/projects.tsv`(repo절대경로 TAB 슬러그), `~/.claude/kc/queue.tsv`(unix시각 TAB session_id TAB cwd TAB 슬러그 TAB transcript경로). 훅과 명령 모두 이 형식을 따른다. 테스트에서는 `KC_DIR` 환경변수로 위치를 재정의한다
- vault 노트 규칙의 SSOT는 `vault/_meta/conventions.md` — 모든 명령은 실행 전 이 파일을 읽는다
- 컨텍스트 노트의 frontmatter `topics:`와 본문 `## 연관` 위키링크는 **항상 쌍으로** 생성
- 초안 생성 시 비밀정보(자격증명·비밀키·내부 전용 URL) 제외

```bash
#!/bin/bash
# kc 훅·명령 공통 — 로컬 상태 파일 경로와 조회 함수. 외부 의존성 없음.

KC_DIR="${KC_DIR:-$HOME/.claude/kc}"
KC_CONFIG="$KC_DIR/config"          # KEY=VALUE (VAULT_PATH, AUTHOR)
KC_PROJECTS="$KC_DIR/projects.tsv"  # <repo절대경로>TAB<슬러그>
KC_QUEUE="$KC_DIR/queue.tsv"        # <unix시각>TAB<session_id>TAB<cwd>TAB<슬러그>TAB<transcript경로>

kc_configured() { [ -f "$KC_CONFIG" ]; }

# $1 = 디렉토리. 등록 repo 경로와 같거나 그 하위면 슬러그 출력, 아니면 빈 출력
kc_project_slug() {
  [ -f "$KC_PROJECTS" ] || return 0
  awk -F'\t' -v d="$1" '$1 != "" && (d == $1 || index(d, $1 "/") == 1) { print $2; exit }' "$KC_PROJECTS"
}

# $1 = session_id. 대기열에 이미 있으면 0
kc_in_queue() {
  [ -f "$KC_QUEUE" ] || return 1
  awk -F'\t' -v s="$1" '$2 == s { found=1 } END { exit !found }' "$KC_QUEUE"
}
```

### Task 3: 커밋 감지 훅 `commit-capture.sh`

**Files:**

- Test: `tests/hooks/test-commit-capture.sh`

**Interfaces:**
- Consumes: `hooks/lib.sh`의 `kc_configured`, `kc_project_slug`
- Produces: PostToolUse(Bash) 훅. stdin으로 훅 JSON을 받아, `git commit` 명령이었고 kc가 설정된 경우에만 `{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"[kc] ..."}}` JSON을 stdout으로 출력. additionalContext는 Claude에게 `reference/capture-flow.md`(Task 5)를 읽고 캡처(등록 repo) 또는 프로젝트 등록(미등록 repo)을 제안하라고 지시한다. 그 외의 경우 출력 없이 exit 0

- [ ] **Step 1: 실패하는 테스트 작성** — `tests/hooks/test-commit-capture.sh`

```bash
#!/bin/bash
set -u
HERE="$(cd "$(dirname "$0")" && pwd)"
SCRIPT="$HERE/../../hooks/commit-capture.sh"
pass=0; fail=0

expect_match() { # $1=이름 $2=JSON입력 $3=출력에 포함돼야 할 문자열
  out=$(printf '%s' "$2" | "$SCRIPT" 2>/dev/null)
  if printf '%s' "$out" | grep -q "$3"; then pass=$((pass+1)); else fail=$((fail+1)); echo "FAIL: $1 (out=$out)"; fi
}
expect_silent() { # $1=이름 $2=JSON입력
  out=$(printf '%s' "$2" | "$SCRIPT" 2>/dev/null)
  if [ -z "$out" ]; then pass=$((pass+1)); else fail=$((fail+1)); echo "FAIL: $1 (out=$out)"; fi
}
json() { printf '{"cwd":"%s","tool_input":{"command":"%s"}}' "$1" "$2"; }

[ -x "$SCRIPT" ] || { echo "FAIL: hooks/commit-capture.sh 없거나 실행권한 없음"; exit 1; }
export KC_DIR="$(mktemp -d)"
printf 'VAULT_PATH=/tmp/v\nAUTHOR=t\n' > "$KC_DIR/config"
printf '/repo/a\tproj-a\n' > "$KC_DIR/projects.tsv"

expect_match  "등록 repo의 git commit → 신호"        "$(json /repo/a 'git commit -m x')" "additionalContext"
expect_match  "등록 repo 신호에 슬러그 포함"          "$(json /repo/a 'git commit -m x')" "proj-a"
expect_match  "git -C 형태도 감지"                    "$(json /repo/a 'git -C /repo/a commit -m x')" "additionalContext"
expect_match  "미등록 repo → 등록 제안 신호"          "$(json /other 'git commit -m x')" "미등록"
expect_silent "commit 아님(git status)"               "$(json /repo/a 'git status')"
expect_silent "git 없는 commit 단어(echo commit)"     "$(json /repo/a 'echo commit')"
expect_silent "JSON 아닌 입력"                        "notjson"

rm "$KC_DIR/config"
expect_silent "kc 미설정이면 침묵"                    "$(json /repo/a 'git commit -m x')"

echo "pass=$pass fail=$fail"
[ "$fail" -eq 0 ]
```

```bash
#!/bin/bash
# PostToolUse(Bash) 훅: git commit 감지 시 Claude에게 캡처 제안 신호를 보낸다.
# 신호만 보낸다 — API 호출·vault 쓰기 금지. 어떤 경우에도 세션을 막지 않는다(항상 exit 0).
set -uo pipefail
HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$HERE/lib.sh"
PLUGIN_ROOT="$(cd "$HERE/.." && pwd)"

input=$(cat)

CMD=$(printf '%s' "$input" | python3 -c '
import json, sys
try:
    d = json.load(sys.stdin)
except Exception:
    sys.exit(0)
print(d.get("tool_input", {}).get("command", "") or "")' 2>/dev/null) || true
CWD=$(printf '%s' "$input" | python3 -c '
import json, sys
try:
    d = json.load(sys.stdin)
except Exception:
    sys.exit(0)
print(d.get("cwd", "") or "")' 2>/dev/null) || true

[ -n "${CMD:-}" ] || exit 0
# "git [전역옵션] commit" 형태만 감지 (git log/status, echo commit 등 오탐 방지)
printf '%s' "$CMD" | grep -Eq '(^|[;&|[:space:]])git[[:space:]]+((-C|-c)[[:space:]]+[^[:space:]]+[[:space:]]+)*(-[^[:space:]]+[[:space:]]+)*commit([[:space:]]|$)' || exit 0
kc_configured || exit 0

SLUG="$(kc_project_slug "${CWD:-}")"
if [ -n "$SLUG" ]; then
  CTX="[kc] git commit 감지 — 작업이 일단락된 것으로 보임 (프로젝트: $SLUG). $PLUGIN_ROOT/reference/capture-flow.md 를 읽고, 기록 가치가 있으면 그 절차대로 사고의 흐름 기록을 제안하라. 사소한 커밋(오타·포맷 등)이면 아무것도 하지 말고 언급도 하지 말 것."
else
  CTX="[kc] git commit 감지 — 이 repo(${CWD:-알 수 없음})는 kc에 미등록. $PLUGIN_ROOT/reference/capture-flow.md 의 '프로젝트 등록' 절차대로 등록을 제안하고, 등록되면 이어서 기록을 제안하라. 이 세션에서 이미 등록을 거절했다면 다시 제안하지 말 것."
fi

CTX="$CTX" python3 -c '
import json, os
print(json.dumps({"hookSpecificOutput": {"hookEventName": "PostToolUse",
      "additionalContext": os.environ["CTX"]}}, ensure_ascii=False))'
exit 0
```

```markdown
# Vault 쓰기 공통 절차 (git flow)

vault에 노트를 쓰는 모든 동작은 이 절차를 따른다. 사용자가 git 명령을 직접 다루게 하지 않는다.

## 절차

1. 밀린 커밋 확인: `git -C "$VAULT_PATH" log --oneline @{u}..` 출력이 있으면 먼저 `git -C "$VAULT_PATH" push` 시도
2. `git -C "$VAULT_PATH" pull --rebase`
3. 노트 생성/수정 — **반드시 사용자 검토·승인을 거친 내용만**
4. `git -C "$VAULT_PATH" add <파일들>` 후 커밋. 메시지 형식(한국어):
   `kc: <프로젝트슬러그|topics|큐레이션>: <무슨 컨텍스트인지 한 줄>`
5. `git -C "$VAULT_PATH" push`

## 예외 처리

- **pull --rebase 충돌**: 충돌 파일을 열어 양쪽 의도를 모두 보존하는 병합을 시도한다.
  컨텍스트 노트는 append 위주라 대부분 양쪽 내용을 다 살리면 된다.

  해결 후 `git -C "$VAULT_PATH" add <해결파일>` → `git -C "$VAULT_PATH" rebase --continue`
- **push 실패(네트워크 등)**: "커밋은 로컬에 안전하게 남아 있고, 다음 kc 명령이 자동으로
  push를 재시도한다"고 사용자에게 알리고 정상 종료한다
```

````markdown
     `templates/inbox-README.md` → `inbox/README.md`

5. **로컬 설정 생성**:
   ```bash
   mkdir -p ~/.claude/kc
   cat > ~/.claude/kc/config <<EOF
````
